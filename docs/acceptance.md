## 课程实库复现实验

1. 冻结字段映射、图谱快照或分支、模型具体型号、Skill、知识库版本和代码提交。设置 `CODE_COMMIT` 为实际提交哈希。
2. 用当前图谱实体准备 KB30。每例执行并保存非空结果，再由两名同学核对方向、实体、机制和去重口径。KB JSON 的结构见 `backend/data/kb.demo.json`。
3. 由指定评审独立编制黄金集。保持 10/12/8 分布。按 `backend/evaluation/gold.demo.json` 填写问题、难度及预期稳定 ID 集合或计数。如需校验机制，设置 `mechanisms`。必要路径可用 `required_paths`，条目包含 `mechanism` 和遍历顺序的 `node_ids`。黄金集仅交给评测工具。
4. 运行全量评测后人工复核路径遗漏与总结。固定同一图谱、模型和预算进行对照。使用 `--no-examples` 测试去除检索的对照组，使用 `LLM_SEMANTIC_RERANK=1` 对比 TF-IDF 与模型重排。
5. 记录正确题数、P95 与失败类型。验收目标为 30 题至少正确 27 题，交互 P95 不超过 20 秒。拒绝、超时及执行结果不完整均判业务失败。评测器存在失败项时返回非零退出码。

将开发集、盲测集、实库原始记录放在团队授权的存储位置。仓库中的样例集用于自动化回归，随代码可见。公开仓库时仅提交确认可公开的文件。
